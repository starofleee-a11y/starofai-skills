# 규제 산업 AI 전사 도입 설계서

SC제일은행은 2026년 7월 전 직원에게 M365 코파일럿을 열었다. 발표자 이성훈 부장의 요지는 "AI 기능보다 승인 가능한 운영 모델을 먼저"였다. 이 스킬은 그 순서(규제 확인 → 승인 → 보안 → 사용자 책임 → 확산)를 우리 조직에 맞춰 문서로 만든다.

> 이 스킬은 법률 자문이 아니다. 규제 해석은 반드시 사내 법무·컴플라이언스와 감독기관 안내로 최종 확인한다.

## 1. 입력 받기
모르는 칸은 "모름"으로 두고 진행한다.
- 업종(은행·보험·증권·카드·의료·공공 등), 직원 수, 본사가 해외인지
- 도입하려는 AI 도구와 형태(SaaS인지, 사내 구축인지)
- AI에 들어갈 데이터 종류: 고객 식별정보, 개인신용정보, 가명정보, 사내 문서, 회의록, 이메일
- 이미 쓰는 협업 도구(M365, Google Workspace 등)와 망분리 상태
- 사내 위원회 목록(정보보호위원회, AI 윤리위원회, 리스크, 감사 등)

## 2. 규제 해당 여부 점검표
아래 질문에 예/아니오/모름으로 답하는 표를 만든다.
| 질문 | 답 | 의미 |
|---|---|---|
| AI가 고객 고유식별정보나 개인신용정보를 처리하나? | | 예면 SaaS 망분리 예외 대상이 아님(2026년 4월 금융위 개정 기준) |
| 가명정보를 쓰나? | | 예면 혁신금융서비스 지정 절차가 별도로 필요 |
| 침해사고 대응기관 평가를 받은 SaaS인가? | | 아니면 예외 요건 미충족 |
| 접속 단말기 보호대책이 있나? | | |
| 반기 1회 통제 점검과 정보보호위원회 보고 체계가 있나? | | |
금융업이 아니면 해당 업권 규정(의료법, 공공 클라우드 보안인증 등)으로 질문을 바꾼다.
결론은 세 가지 중 하나로 낸다: **바로 진행 가능 / 데이터 범위를 줄이면 가능 / 별도 승인 필요**.

## 3. 데이터 범위 줄이기
"고객 정보는 넣지 않는다"는 단서 하나로 절차가 크게 줄어든다(SC제일은행 사례). 다음을 정리한다.
- AI 허용 업무: 회의 요약, 메일 초안, 문서 초안, 시장조사, 제안서 구조 잡기
- AI 금지 업무: 고객 식별정보·신용정보가 들어가는 상담 기록, 여신 심사 원본
- 금지를 지키는 기술 장치(DLP 규칙, 민감정보 레이블)와 사람 장치(서약, 교육)

## 4. 내부 승인 로드맵
위원회를 **순서대로** 배치한 표를 만든다. 기본 순서 예시:
정보보호위원회 → AI 윤리위원회 → 컴플라이언스·법무 → 비재무 리스크 → 데이터 거버넌스 → 경영위원회 → 감사위원회.
위원회마다 "그 위원회가 가장 먼저 물을 질문 2개"와 "제출할 자료 1개"를 적는다. 해외 본사가 있으면 본사 승인 단계를 맨 앞에 넣는다.

## 5. 다층 보안 통제
5개 층마다 지금 상태(있음/부분/없음)와 할 일을 적는다.
1. 접근 권한(누가 어떤 문서까지 AI로 볼 수 있나, 권한 과다 공유 정리)
2. 민감정보 레이블
3. DLP(유출 방지) 규칙
4. 사용 로그 모니터링
5. 책임 있는 AI 원칙(결과 검토 의무, 금지 용도)

## 6. 사용자 서약서(Attestation) 초안
라이선스 신청 시 제출하는 설문 형식으로 8문항 안팎을 만든다. 반드시 포함: AI 결과는 사용자가 검토할 책임, 금지 데이터 목록, 잘못된 결과를 발견했을 때 신고 경로. 서약 제출과 확인이 끝나야 라이선스를 할당하는 흐름도 함께 적는다.

## 7. 일정
"TF 발족 → 승인 → 시범 → 전면 도입"을 월 단위로 적는다. SC제일은행은 TF 발족(2026년 3월)부터 전면 도입(7월)까지 약 4개월이 걸렸다. 우리 조직의 위원회 수와 개최 주기로 기간을 다시 계산한다.

## 8. 출력
마크다운 문서 1개: `규제 점검표 → 결론 → 데이터 허용/금지 표 → 승인 로드맵 → 보안 5층 표 → 서약서 초안 → 월별 일정 → 다음 행동 3개`. 2~3쪽. 모르는 건 "확인 필요"로 남기고 지어내지 않는다.
