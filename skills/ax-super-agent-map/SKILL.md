# AX 슈퍼 에이전트 맵

월마트는 부서마다 생긴 AI 에이전트가 직원·고객을 헷갈리게 하자, **고객(Sparky)·직원(Associate)·파트너(Marty)·개발자(Developer)** 4개의 '입구'로 묶었다. 작은 전문 에이전트는 뒤에서 일하고 사람은 입구만 기억한다. 이 스킬은 그 설계를 우리 조직에 적용한다.

## 1. 입력 받기
사용자에게 아래를 물어본다(모르는 칸은 비워도 된다). 파일·표·메모 붙여넣기 모두 가능.
- 회사/팀 한 줄 소개, 업종, 인원
- 지금 쓰는 AI 봇·챗봇·자동화 목록 (이름 · 누가 쓰나 · 하는 일 · 연결된 시스템)
- 사람이 반복하는 업무 상위 10개 (누가 · 빈도 · 소요 시간)
- 이미 막힌 곳 (예: "봇이 답은 주는데 처리는 사람이 다시 해야 함")

## 2. 분류 (As Is 표)
모든 항목을 한 표로 정리한다.

| 항목 | 사용자 그룹 | 하는 일 | 실행까지 이어지나? | 월 소요 시간 |
|---|---|---|---|---|

- **사용자 그룹**: 고객 / 직원 / 파트너(공급사·셀러·외주) / 개발자·운영 중 하나. 애매하면 "누가 이 창을 여는가"로 판단한다.
- **실행까지 이어지나?**: 추천·답변만 하면 `추천만`, 주문·등록·발송까지 처리하면 `실행`. `추천만`이 많은 그룹이 첫 번째 병목이다.

## 3. 슈퍼 에이전트 입구 설계 (To Be)
사용자 그룹마다 입구 1개. 조직이 작으면 2~3개로 줄여도 된다. 각 입구에 대해:
- **이름과 한 줄 약속** (예: "영업팀 입구 — 고객사 질문부터 견적서 초안까지")
- **첫 화면 질문 3개** (사용자가 가장 자주 할 말)
- **하위 전문 에이전트** 3~6개 (2단계 표의 항목을 흡수·통합)
- **연결할 시스템** (CRM, ERP, 메신저, 드라이브 …)과 `실행` 가능 여부
- **KPI 1개** (시간 절감, 처리 건수, 전환율 등)

## 4. 2차 승인 규칙
에이전트가 **준비만 하고 실행은 별도 승인**을 받아야 하는 행동을 입구별로 표시한다. 기본 5종:
돈 이동(결제·환불·송금) / 운영 데이터 삭제 / 권한 변경 / 민감정보 외부 전송 / 관리자 권한 위임.
승인자는 사람 또는 규칙 엔진(금액 한도 등)으로 적는다.

## 5. 90일 로드맵
- **0~30일**: `추천만` 비율이 가장 높은 입구 1개를 골라 실행 연결 1건 완성. 성과 측정은 `ai-impact-experiment` 스킬로 실험 설계.
- **31~60일**: 같은 입구에 하위 에이전트 2~3개 흡수, 기존 개별 봇 종료 공지.
- **61~90일**: 두 번째 입구 착수. 첫 입구 KPI를 A/B 결과로 보고.

## 6. 출력
마크다운 설계서 1개: `As Is 표 → 입구별 To Be 카드 → 2차 승인 표 → 90일 로드맵 → 다음 행동 3개`.
각 입구 카드는 5줄 이내. 전체 1~2쪽. 과장 없이, 모르는 건 "확인 필요"로 남긴다.
